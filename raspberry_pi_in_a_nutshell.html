Introduction & learning objectives

What Raspberry Pi is, what it does, and where it fits.

Definition

Raspberry Pi is a family of compact, low-cost single-board computers. A typical board combines a processor, memory, connectivity and interfaces on one circuit board. With an operating system and storage, it can run applications, control peripherals and act as an edge computer in IoT systems.

It is a product family, not one fixed specification. Ports, RAM, wireless features and performance depend on the model.

Why it matters

It connects software to the physical world. Students can prototype sensor dashboards, automation systems, data loggers, network services and camera-based applications using Linux and high-level languages.

Remember: Raspberry Pi is a general-purpose computer. A microcontroller board is often a better fit for very low-power, direct, deterministic control.

Learning objectives

  • Identify major board components.
  • Explain boot and software workflow.
  • Distinguish GPIO, I²C, SPI, UART and networking.
  • Apply safe voltage/current practices.
  • Understand a simple Python GPIO program.
  • Choose a platform for a project.
  • Recognize deployment, reliability and security concerns.

03

System architecture and signal flow

Hardware, OS, software and external devices work together.

Electrical safety: Never connect a 5 V signal directly to a typical 3.3 V GPIO. Do not drive motors or high-current loads directly from GPIO; use a suitable driver and protection.

Boot sequence

  1. Power is applied through a compatible supply.
  2. Firmware/boot process initializes hardware.
  3. Boot process loads the operating system from supported storage.
  4. Linux starts services, networking and user programs.
  5. Your application reads inputs, processes data and controls outputs.

Common interfaces

  • GPIO: digital input/output.
  • I²C: two-wire addressed bus.
  • SPI: synchronous serial interface.
  • UART: asynchronous serial communication.
  • USB / Ethernet / Wi-Fi: peripherals and networking.

Interface availability and configuration depend on the model and OS.

04

Getting started: setup workflow

A repeatable path from storage to a working project.

  1. Choose a model. Match compute, memory, connectivity, ports, power and budget to the application.
  2. Prepare storage. Use the official Raspberry Pi imaging tool or currently recommended setup method to write a compatible OS image.
  3. Configure first boot. Set username, password, locale and network details using the supported setup flow.
  4. Power on. Connect peripherals and a compatible supply; allow first boot to finish.
  5. Update responsibly. Follow the OS documentation and install only required packages.
  6. Develop and test. Begin with a small script, validate each interface and keep a known-good backup.
  7. Deploy securely. Use unique credentials, restrict remote access, monitor services and document recovery.
Headless option: Configure network access and remote login through the supported setup workflow, then connect from another computer. Avoid exposing remote access directly to the public internet without a secure design.

GPIO basics and starter code

Conceptual LED example; verify physical wiring and pin numbering first.

Use a resistor in series with an LED. GPIO is a logic interface, not a power supply for arbitrary loads.

Python example (illustrative)

# Example for a compatible Raspberry Pi OS setup with gpiozero
from gpiozero import LED
from time import sleep

led = LED(17)  # BCM GPIO numbering; verify your wiring

try:
    while True:
        led.on()
        sleep(1)
        led.off()
        sleep(1)
except KeyboardInterrupt:
    led.off()
    led.close()
Before running: Confirm the library is installed and compatible with your OS. Confirm BCM versus physical pin numbering. Disconnect power before changing wiring.

How the program works

  1. Imports the LED abstraction and delay function.
  2. Associates an LED object with a GPIO pin.
  3. Turns the output on and off at one-second intervals.
  4. On keyboard interruption, turns the LED off and releases the resource.

Worked example 1 — Estimate sensor data volume

Problem: Four sensor values are each stored as a 4-byte number, once every 10 seconds. Estimate raw payload for one day, excluding metadata.

Bytes per record = 4 × 4 = 16 bytes. Records per day = 86,400 / 10 = 8,640.

Daily raw payload = 16 × 8,640 = 138,240 bytes ≈ 135 KiB

Real storage is higher when timestamps, delimiters, logs or database overhead are included.

Worked example 2 — LED resistor estimate

Given: illustrative GPIO HIGH = 3.3 V, LED forward voltage = 2.0 V, target current = 5 mA.

R = (VGPIO − VLED) / I = (3.3 − 2.0) / 0.005 = 260 Ω

A nearby standard value of 270 Ω gives about (3.3−2.0)/270 ≈ 4.8 mA. Check actual component ratings and GPIO limits; this is an estimate, not a universal recommendation.

Worked example 3 — Sampling rate

Problem: A sensor is sampled every 250 ms. How many samples are planned in 60 seconds?

Use N = T / Ts, where T = 60 s and Ts = 0.25 s.

N = 60 / 0.25 = 240 samples

Real OS scheduling, sensor conversion time and bus delays can introduce jitter or missed samples.

Industry design considerations

  • Power: account for USB/camera loads and use a suitable supply.
  • Thermal: sustained workloads may need cooling.
  • Storage: use reliable media, backups and graceful shutdown.
  • Security: patch software, restrict ports and encrypt communications.
  • Reliability: supervise services, log faults and plan recovery.
  • Interfaces: check datasheets and use proper drivers or isolation.

Core electronics & embedded interview preparation

Expand each question to review a concise answer.

1. What is Raspberry Pi?

A family of single-board computers that can run an OS and general-purpose applications; exact features depend on model.

2. How does an SBC differ from a microcontroller?

An SBC commonly runs a full OS with networking and processes. A microcontroller is usually firmware-centric, lower power and suitable for direct control tasks.

3. What is GPIO?

General-purpose input/output pins used for digital signals and supported alternate functions. Electrical limits must be observed.

4. Why not connect 5 V directly to a typical Pi GPIO?

Typical GPIO is 3.3 V logic and not 5 V tolerant. A higher voltage can damage the SoC; use a proper level shifter.

5. When might you choose I²C instead of SPI?

I²C uses two signal wires and addresses devices on the bus. SPI uses clock, data and chip-select signals and can provide higher throughput. Device and speed requirements decide.

6. What is headless operation?

Running without a dedicated display and keyboard, commonly managed over a network. Securely configure credentials and remote access.

7. An I²C sensor is not detected. How do you debug it?

Check power, ground, voltage compatibility, SDA/SCL mapping, enabled interface, pull-ups, address, wiring and datasheet; test with a known-good device.

8. Why use a driver for a motor?

Motors need more current than GPIO can provide and are inductive loads. Use an appropriate driver and protection circuit.

9. What can happen if power is removed during a write?

File or data corruption may occur. Use reliable storage, clean shutdowns, backups and recovery handling.

10. How do you harden an IoT Pi deployment?

Patch software, use unique credentials or keys, restrict remote access, encrypt traffic, protect secrets and minimize enabled services.

11. How would you restart a program after a crash?

Use a process supervisor/service with a restart policy, logs, health checks and safeguards against endless restart loops.

12. When is Raspberry Pi not the best choice?

When hard real-time timing, extremely low power, high-volume unit cost, certification or a tiny footprint dominates; consider an MCU or industrial controller.

Quick revision sheet

Last-minute recap, formulae, limitations and troubleshooting.

Key facts

  • Raspberry Pi is a single-board computer family.
  • Typical workflow: OS → application → interface → device/service.
  • Pin numbering can mean BCM GPIO numbers or physical header positions.
  • Typical GPIO is 3.3 V logic; never assume 5 V tolerance.
  • General-purpose Linux is not automatically hard real-time.

Formula sheet

Sampling count:

N = T / Ts = T × fs

Ohm's law and power:

V = IR   |   P = VI

LED resistor estimate:

R ≈ (VGPIO − VF) / ILED

Check real ratings and units before circuit use.

Advantages

  • Runs an OS and high-level languages.
  • Useful networking, storage and community support.
  • Rapid prototyping and system integration.

Limitations

  • Needs suitable supply and storage.
  • GPIO is not a high-current or 5 V tolerant interface.
  • Scheduling and storage writes affect deterministic behavior.
  • Model and peripheral compatibility must be checked.
